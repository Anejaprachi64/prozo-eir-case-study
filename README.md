## Run locally (≈5 minutes)
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                         # all pure-pip wheels, no system packages
python run.py                                           # -> http://127.0.0.1:5000
```
Each page has a **"run on the bundled sample"** button, so a reviewer can see results with zero uploads.
Tested on Python 3.12. First CS1 run downloads nothing (OCR models ship inside the `rapidocr-onnxruntime` wheel).

```bash
pytest -q          # 23 tests: name-matching matrix, CS2 vs ground truth, HTTP-level uploads incl. bad input
python scripts/run_samples.py        # regenerates sample_outputs/ without the server
python -m app.cs1_parcels <image_folder> out.csv   # CS1 as a CLI
```

## How the "common requirements" are met
* **Usable by a non-technical person:** upload → progress bar → results table → download buttons (`app/templates`, `app/static/app.js`).
* **Big batches don't freeze the screen / can leave and come back:** every upload becomes a *job* run on a background thread pool (`app/jobs.py`). State is persisted to `data/jobs/<id>/`, so `/jobs/<id>` (and "Recent jobs") works after closing the tab or restarting the server. Jobs that were mid-flight during a restart are marked as interrupted rather than hanging forever.
* **Bad input gives a clear message, not a crash:** empty upload, corrupt image/zip/PDF/Excel, wrong file in the wrong slot, scanned PDF, missing columns, zero revenue, etc. all raise a `UserError` that is shown on the page. Covered in `tests/test_app.py`.
* **No secrets in repo:** SMTP / Slack / Ollama settings come from env vars (`.env.example`).
* **Free path:** nothing paid is used anywhere; the only optional extra is a *local* Ollama model for re-wording CS3 insights.

## Layout

## Important honesty note (read first)
The three dataset links in the brief were not reachable from the environment this was built in, so **all sample data is synthetic**, generated by the scripts in `scripts/` to mimic the layouts described in the brief. Accuracy figures in the docs are measured on that synthetic data, which I wrote, so they prove the logic works but **not** real-world accuracy. The first thing to do with real files is run them and read the parse-sanity warnings (CS2) / flags (CS1) — each doc lists what is most likely to need tuning.
